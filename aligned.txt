VVV Agents — Development Technical Reference (Replit)
Overview

The VVV Agents monorepo implements an agent‑orchestrated capacity broker for the Venice token (VVV) and its Diem derivative on the Base blockchain. It combines Coinbase AgentKit smart‑wallet support, a FastAPI broker API, LangGraph/LangChain orchestration and autonomous key management for Venice’s AI service. The goal is to let agents stake VVV, mint DIEM, and resell or use AI capacity automatically. This document provides a streamlined technical reference tailored to AI/ML engineers coming from an IT/STEM background, focusing on the practical steps and pitfalls discovered during recent development.

Repository structure recap

apps/broker‑api – FastAPI server for issuing scoped keys, proxying chat calls and enforcing rate limits.

apps/cli – Command‑line interface for interacting with the broker (create/list tenants, set limits, etc.).

services/ – Wallet, staking, Diem mint/burn, Venice key issuance, market data and risk abstractions.

agents/ – Agents for staking (StakeMaster), Diem arbitrage (ArbiDiem), capacity brokering, treasury management and quorum decisioning.

graph/ – LangGraph nodes and workflows (observe, decide, execute).

libs/ – Thin Venice API client, AgentKit wrappers, pricing helpers, telemetry.

Refer to the root README.md for a full project overview; this document focuses on day‑to‑day development tasks and common troubleshooting.

1. Workflow for pushing code to Replit

Clone the repo and switch to the replit branch. Work only on this branch for your hosted environment.

Install dependencies using uv (preferred):

curl -LsSf https://astral.sh/uv/install.sh | sh
# Add uv to PATH for the current shell.  On Replit:
export PATH="$HOME/.local/bin:$PATH"
uv venv
uv sync --extra dev  # pulls dev dependencies, including pytest


If uv is not on your PATH, call it via its full path (~/.local/bin/uv).

If you prefer pip/virtualenv, use the fallback instructions in the project README.

Configure environment variables: Copy .env.example to .env and fill in values:

BROKER_ADMIN_TOKEN – secret for admin endpoints.

BROKER_BASE_URL – the URL of your running broker (e.g., https://<username>.worf.replit.dev).

Venice API configuration (critical):

VENICE_API_BASE_URL – set to https://api.venice.ai/api/v1 unless your deployment differs (see Section 2).

VENICE_PARENT_KEY – a parent/root inference key that can create sub‑keys; using a normal VENICE_API_KEY will cause 403/404 on subkey creation.

Optional: VENICE_CREATE_SUBKEY_PATH if your Venice deployment uses a non‑standard path for subkeys.

BASE_RPC_URL, WALLET_PROVIDER and associated keys for AgentKit smart‑wallet/EOA providers if you test on‑chain flows.

Run the broker locally (for testing) or in Replit:

# Local testing with uv
uv run uvicorn app:app --app-dir apps/broker-api --reload

# On Replit, the `Run` button launches this automatically using `main.py`.


The API serves Swagger UI at /docs, Redoc at /redoc, health metrics at /health, and Prometheus metrics at /metrics. You need an Authorization: Bearer $BROKER_ADMIN_TOKEN header to access admin endpoints.

Use the CLI to manage tenants and limits:

python apps/cli/main.py broker:tenants:list
python apps/cli/main.py broker:limits:set --tenant t1 --window 60 --max 100


The CLI uses BROKER_BASE_URL and BROKER_ADMIN_TOKEN from your .env. See python apps/cli/main.py --help for all commands.

Run the test suite (optional, but recommended when changing code):

uv run pytest -q


If uv is unavailable, python -m pytest -q works if you installed dependencies via pip.

Tests include stubs for sqlmodel and the Venice client, so you do not need running Postgres or external services unless you are explicitly testing those.

2. Venice API pitfalls and tips
Base URL selection

Venice’s OpenAPI spec is deployed at either …/openapi.json or …/api/openapi.json. You must set VENICE_API_BASE_URL accordingly:

Probe the endpoint without /api:

curl -fsSL "${BASE_URL%/}/openapi.json" || true


If it returns 200, set VENICE_API_BASE_URL=${BASE_URL%/}. If it returns 404, try with /api/openapi.json. If that works, set VENICE_API_BASE_URL=${BASE_URL%/}/api
docs.venice.ai
.

Official Venice uses https://api.venice.ai/api/v1 
docs.venice.ai
. Therefore, set VENICE_API_BASE_URL=https://api.venice.ai/api/v1 for production.

Parent key vs. API key

VENICE_PARENT_KEY (sometimes called a root key) has privileges to create sub‑keys. It’s issued via the wallet challenge flow. Without this key, calls like POST /v1/keys/sub or POST /api/v1/api_keys/generate_web3_key will return 404/403
docs.venice.ai
.

VENICE_API_KEY is a standard inference key; it can be used for chat calls but not for sub‑key creation. The broker falls back to this key if VENICE_PARENT_KEY is unset, but you must ensure it actually has parent privileges to avoid errors.

Avoid double slashes

When building URLs in shell scripts:

BASE_URL="https://api.venice.ai/api/v1"
# WRONG: This will call //v1/models
curl "$BASE_URL/v1/models"
# RIGHT:
curl "${BASE_URL%/}/v1/models"


In code, apply .rstrip('/') on the base URL before concatenating paths
docs.venice.ai
.

Generating API keys with a Web3 wallet

For autonomous agents, you can programmatically obtain API keys via the Generate API Key with Web3 Wallet flow:

GET /api/v1/api_keys/generate_web3_key to receive a token. You must authenticate with your parent key.

Sign the token with your wallet’s private key (must hold staked sVVV).

POST /api/v1/api_keys/generate_web3_key with JSON body including apiKeyType, consumptionLimit (usd/diem/vcu), description, expiresAt, address, signature and the token
docs.venice.ai
.

The response contains the new apiKey object and consumption limits. Save the key and use it for chat requests or sub‑key creation.

Subkey creation

The older route POST /v1/keys/sub can still be used in some deployments. The broker’s default expects this path. If your Venice deployment uses a different path, set VENICE_CREATE_SUBKEY_PATH accordingly. Example:

export VENICE_CREATE_SUBKEY_PATH=/v1/keys/subkey

3. Troubleshooting common issues
Missing uv or PATH problems

After running the uv installer, binaries are placed under ~/.local/bin. If uv is not found, add this directory to your PATH:

export PATH="$HOME/.local/bin:$PATH"


Alternatively, call uv directly by its absolute path: ~/.local/bin/uv ....

Dependency installation failures

If uv sync fails due to missing sqlmodel or other extras, ensure you pass --extra dev to install development dependencies.

On Replit, the default environment may not allow writing to /home/runner/.bashrc; you can ignore these warnings. Use the export PATH command each time or add it to your workspace ~/.profile if supported.

Tests failing with sqlmodel errors

The unit tests stub out sqlmodel to avoid requiring a real database. If you see TypeError: Tenant.__init_subclass__ when running pytest, ensure that the stub is applied before importing db.models. The repository’s tests/test_admin_counters_endpoint.py demonstrates the proper approach.

404 when creating tenants

Ensure you are using the correct VENICE_API_BASE_URL (see Section 2) and that VENICE_PARENT_KEY has sub‑key privileges.

Confirm your BASE_URL or BROKER_BASE_URL environment variables do not end with /; use ${BASE_URL%/} when composing requests.

When debugging, you can seed apps/broker-api/tenants.json with a known key to bypass sub‑key creation temporarily, but do not do this in production.

4. Practical “cheat sheet”
Creating a tenant via the Broker API
# Assumes BROKER_BASE_URL and BROKER_ADMIN_TOKEN are set
curl -sS -X POST "${BROKER_BASE_URL%/}/v1/tenants" \
  -H "Authorization: Bearer $BROKER_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "tenant_id": "t1",
        "label": "Team A",
        "quota": null,
        "expires_at": "2025-12-31T23:59:00Z"
      }'


The broker requests a sub‑key from Venice using your VENICE_PARENT_KEY and returns the new tenant record (check apps/broker-api/tenants.json or SQL). If the call fails with 404 or 401, revisit Section 2.

Copy the subkey returned for the tenant and set it as the bearer for future chat calls.

Listing tenants and limits (CLI)
python apps/cli/main.py broker:tenants:list
python apps/cli/main.py broker:limits:get --tenant t1

Proxying chat via the broker
export SUBKEY=<tenant-subkey>
curl -sS -H "Authorization: Bearer $SUBKEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "Hello"}]}' \
  "${BROKER_BASE_URL%/}/v1/chat"

Viewing and managing counters

Debug counters (admin only): GET /v1/debug/counters?tenant_id=t1&limit=20. Accepts scope, bucket_seconds, asc, since, until filters.

CLI: python apps/cli/main.py counters:show --tenant t1 --scope chat --limit 20 --json.

Compact counters from KV to SQL: python apps/cli/main.py data:compact-counters --force.

5. Additional notes for AI/ML engineers

Agentic architecture: The broker is a component of a larger multi‑agent system. The agents/ directory hosts various agents; graph/ defines how they interact. For local development, you can run workflows with python apps/cli/main.py run:quorum --dry-run.

On‑chain integration: Interacting with VVV/DIEM on Base requires connecting a wallet via AgentKit. See services/wallet and services/staking for examples. The default Replit environment does not include RPC endpoints; add BASE_RPC_URL to use Mainnet or Sepolia.

DIEM tokenomics: The broker uses services/diem and services/staking to mint/burn DIEM and stake VVV. These modules are currently stubbed; they should be completed to align with the official VVV tokenomics and DIEM trading on Aerodrome.
